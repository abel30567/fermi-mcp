# Worker Package

The main Cloudflare Worker that serves as the MCP server.

## Key Files

- **wrangler.jsonc** — Generated by `bootstrap.sh`. Contains account-specific resource IDs. Gitignored.
- **wrangler.template.jsonc** — Template with `__PLACEHOLDER__` tokens. Committed.
- **vitest.config.ts** — Test configuration using Cloudflare Workers pool
- **vitest.contract.config.ts** / **wrangler.test.jsonc** — MCP contract project: boots the real worker entry and drives it over `/mcp` via `SELF.fetch` (`test/contract/`)
- **wrangler.eval.jsonc** — Local-only eval target (see "Running the eval target" in the README); seeded and dumped by `scripts/eval-seed.mjs` / `scripts/eval-dump.mjs`
- **worker-configuration.d.ts** — Auto-generated type definitions for Worker bindings
- **tool-surface.json** — Generated by `bun run tool-surface`: every MCP tool's name, description hash, input schema, risk, mutates and box membership. A contract test fails when the live surface differs; regenerate and commit it when a tool change is intended.

## Contract coverage

Cover a tool with `describeTool('<name>', ...)` from `test/contract/describe-tool.ts`. `tool-coverage.test.ts` fails when a registered tool has no such block, so every new tool needs one.

Outbound HTTP is refused unless a test mocks it with `fetchMock`. The macOS bridge (`http://mac.test`) answers 503 by default; install a fake with `setMacBridge()` from `test/contract/fake-mac.ts`. High-risk tools go through `callApproved()` in `test/contract/approval.ts`.

## Subdirectories

- **src/** — Application source code
- **migrations/** — D1 SQL migrations (applied in order)
- **seeds/skills/** — Built-in skill templates loaded on first deploy
- **public/** — Static assets served by the Worker
- **test/** — Vitest test files

## Commands

```bash
bun run dev           # Local dev server
bun run test          # Unit + contract test projects
bun run test:contract # Contract tests only (real worker over MCP)
bun run tool-surface  # Regenerate tool-surface.json from the live worker
bun run migrate:local # Apply migrations locally
bun run migrate:remote # Apply migrations to production D1
```
